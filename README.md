# FoundryAI — Private Codebase Licensing

**License your private codebase to AI labs. Keep the IP, share the proceeds.**

AI labs license private codebases (with real git history) as training data. FoundryAI aggregates codebases from independent developers and companies, gets them quoted by the buyer for further purchase. 

**This repo does not ask for your code.** It walks you through producing a short, standardized report about your codebase on your own machine, and how to send it to us. If it's a fit, we come back with next steps (NDA, ownership attestation, quote). Code is only ever delivered after you've accepted a quote.

---

## Eligibility

Submit only if **all** of these hold:

- You (or your company) own the code outright. Not built on an employer's time under an IP agreement you don't control, not a fork of someone else's project, no contractor code you don't hold the rights to.
- The code has **never been published** (never on a public GitHub/GitLab, never open-sourced). Public code is worth nothing to the buyer, and "partially published" is heavily discounted.
- It has real git history. A single "initial commit" snapshot is accepted but priced far lower than full history.
- It's a working application, service, or tool — not a tutorial, boilerplate, or scaffold.

Rough guide: 20k+ logical lines of code and 100+ commits is where it starts to be worth everyone's time. Multiple repos that are delivered and priced together count as **one codebase**.

## Step 1 — Install two free tools

- **scc** (Succinct Code Counter): https://github.com/boyter/scc — single binary, download and run.
- **jscpd** (copy/paste detector): `npm install -g jscpd`

---

## Step 2 — Run four commands

Run commands 1–3 **once** in the folder that contains the repository (or the folder holding all repos in the bundle, if you're submitting several as one codebase). Run command 4 **inside each repository** on its default branch (e.g. `main`) and add the results up.

Run them **in this order** — jscpd writes its report into the folder, and scc would count it as code if run afterwards.

```bash
# 1. Logical LOC + Primary Language
scc -x csv .
#    → Logical LOC = the "Code" column total
#    → Primary Language = first row of the Language column (largest Code count)

# 2. Non-Authored LOC (generated / vendored code)
scc -x csv --gen --generated-markers "do not edit,<auto-generated />,<auto-generated>" \
    --exclude-dir vendor,node_modules,dist,build,generated,migrations,Migrations .
#    → sum the "Code" column ONLY for rows ending in "(gen)"; ignore Total

# 3. Duplication Ratio
jscpd . --min-tokens 50 --min-lines 5 --reporters json --ignore "**/*.csv"
#    → take the percentage shown and divide by 100 (e.g. 11% → 0.11)

# 4. Non-Merge Commit Count (run inside each repo, on the default branch)
git log --oneline --no-merges | grep -v -i revert | wc -l
```

Then produce the two report files that get attached to your submission. Write them **outside** the repo folder:

```bash
scc -x csv --format json -o ../scc-report.json .
# jscpd already wrote its JSON report (jscpd-report.json) in step 3 — move it next to scc-report.json
```

One jscpd report per repository; if you have several, zip them together.

## Step 3 — Fill in the report

Use the **FoundryAI — Private Codebase Data Form** (Google Sheets):

**→ [Open the submission form](https://docs.google.com/spreadsheets/d/1miaOOe6b4pZHKqfOb517wtvqFNVkeihn/edit?gid=508056004#gid=508056004)**

1. Open the link and choose **File → Make a copy** (or **Download → Microsoft Excel**) so you have your own editable version.
2. Fill in the **Company Information** block at the top (company name, contact person, contact email, industry, date).
3. Add **one row per codebase** in the Codebase Details table — up to 50. A bundle of repos priced together is one codebase: put it on a single row and enter the combined totals. Totals and the summary are calculated for you — don't edit the grey cells.
4. For fields with a dropdown (Git Delivery Format, Builds & Tests, Private Code Attestation, Primary Language, Industry, Written By), pick from the list. The **Field Definitions** tab explains every field and its accepted values.

Be accurate either way: everything is verified at delivery, and a mismatch (e.g. "full history" promised, squashed history delivered) affects the outcome.

## Step 4 — Send it

Email team@foundryhq.ai with subject `Codebase submission: <company name>` and attach:

1. Your filled-in form — the completed spreadsheet (exported as `.xlsx`)
2. `scc-report.json`
3. `jscpd-report.json` (or a zip of them, one per repo)

**Do not attach source code, archives, or repo links.** The reports contain only counts, file paths, and language breakdowns — no code.

## What happens next

1. We log your submission and reply within a few business days: fit / not a fit / need more info.
2. If it's a fit: short NDA + ownership attestation (you confirm you hold the rights and disclose any contractor or third-party code).
3. We submit it to the AI labs and get a quote. You see the number before anything is delivered.
4. You accept → you deliver the code in the git format you declared, with build command and runtime version (e.g. Node 18, Python 3.11) → payment on buyer acceptance.

## FAQ

**1. Will my code train AI models?**

Yes, that's the purpose. Don't submit if you're not comfortable with that.

**2. Do I lose ownership?**

No. It's a licence. You keep the IP; exact terms come with the quote.

**3. Can I submit code from a previous job?**

Only if your employment/contractor agreement left you the rights — uncommon. When in doubt, don't.

**4. What about dependencies?**

Installed packages (npm, pip, etc.) are fine and are excluded from authored LOC anyway. Vendored or copied-in third-party source must be counted as Non-Authored LOC.

**5. My tests are broken / I have no tests.**

Still submit. Choose "Builds only" or "Not verified" — it affects price, not eligibility.

**6. Code written with AI tools (Copilot, Cursor, etc.)?**

Still eligible. Estimate the human/AI split in the "Written By" field. Pre-2022 commits are a useful reference point.

**7. I have several codebases.**

One submission file per codebase.
